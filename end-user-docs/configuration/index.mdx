# Configuration

The workforce system is configured via a `workforce.toml` file. This page introduces the main sections you can configure.

<Callout type="info">
The configuration is hierarchical: global settings apply to all agents, but you can override them per-agent or per-team.
</Callout>

## Quick Start

A minimal configuration file looks like this:

```toml
[hub]
listen = "0.0.0.0:8090"
data_dir = "./data"

[nats]
url = "nats://localhost:4222"

[llm]
provider = "anthropic"
default_model = "claude-sonnet-4-20250514"
max_tokens = 8192

[[agents]]
id = "default"
workspace = "./data/agents/default"
default = true
```

Place this file in your project root and run:

```bash
workforce serve
```

## Subscription providers

Besides API-key providers, an agent can run on a Claude or ChatGPT plan through three provider kinds, usable anywhere a model spec goes (`provider`, `default_model`, `failover`, `model_preferences` and the other model settings):

- `chatgpt` — the ChatGPT backend, driven by the hub's own agent loop (`chatgpt:gpt-6.1-sol`).
- `claude-code` (alias `claude_code`) — the `claude` CLI on a Claude plan (`claude-code:sonnet`).
- `codex` — the `codex` CLI on a ChatGPT plan, on the remote worker only (`codex:gpt-6.1-sol`).

Two settings belong to them:

```toml
[llm.logins]                      # optional; also per agent in [agents.llm.logins]
tiers = ["agent_user", "global_user", "agent_shared", "system_shared"]   # default
shared_serves = "anyone"          # owner | agent_users | anyone (default)

[subscription]                    # install-wide; read at start-up
chatgpt_direct = false            # allow the chatgpt provider (off by default)
operator = "00000000-0000-0000-0000-000000000000"      # whose plan pays for the hub's own work
max_concurrent_cli_turns = 4      # CLI agent turns at once; 0 = unbounded
max_concurrent_completions = 4    # one-shot CLI calls at once; 0 = unbounded
```

`[llm.logins]` only narrows which logins an agent uses: by default every tier is tried and a shared login serves anyone. See [Subscriptions](/docs/concepts/subscriptions) for what each tier and setting means.

## Environment Variables

Many settings can be overridden via environment variables:

- `WORKFORCE_NATS_URL` – NATS server URL
- `ANTHROPIC_API_KEY` – Anthropic API key (or `OPENROUTER_API_KEY` for OpenRouter)
- `WORKFORCE_LISTEN` – Hub listen address
- `WORKFORCE_LOG_LEVEL` – Log verbosity
- `WORKFORCE_TIMEZONE` – User timezone (IANA name)

## Seeing what is in effect

A setting can come from a built-in default, `workforce.toml`, an agent's own `config.toml` or a change made at runtime, and what is written is not always what is in effect. To find out, ask the agent ("what is your vision model, and where is it set?") or open the agent's **Effective settings** tab.

Each setting is shown with its value, where the value comes from, and a status where it matters:

- **Active** – in effect.
- **Off** – switched off for this agent.
- **Off by install** – the install has it off for every agent.
- **Shadow** – worked out and logged, changing nothing.
- **Inert** – configured but not taking effect, with the reason. For example, an agent that enables know-how while the install has it off, or a vision model that cannot be reached.

Keys and tokens are never shown, only whether one is set and at which vault level. Install-wide settings are shown to admins.

## Additional Configuration Areas

The system includes several advanced configuration areas:

- **Postgres Backend**: Optional shared database for stores like telemetry, identity, and pairing data.
- **Permissions Cascade**: Role-based access control with per-user overrides.
- **MCP Servers**: Connect to external Model Context Protocol servers.
- **OAuth Identity**: Single sign-on with OIDC/OAuth2 providers.
- **Vision & Transcription**: Configure separate AI models for image description and audio transcription.
- **Image Generation**: Opt-in image generation capabilities.
- **Local Agents**: Enable local agent support.
- **Agent Communications**: Oversight for agent-to-agent messages.
- **Daily Briefing**: Scheduled daily summaries.
- **Slack Channel Overrides**: Per-channel customization.
- **AWS S3**: Read-only AWS S3 tool with allowlist and role assumption.
- **Workflows**: Per-owner concurrency limits for workflow execution.
- **Team-Building Games**: Multi-agent games arena (`/games`).
- **AWS Infrastructure Tools**: Read-only tools for ECS, ECR, ELB, RDS and STS.
